# Balance Check (Loop Breaker)

Supports the **BAL** tickets (BAL01 tokens, BAL02 boss difficulty, BAL03 idle
rate, BAL-CSV01 live-linked constants, MONLV01 monster levels).

## Phase 1 — Domain

From `$ARGUMENTS[0]`:
- **combat** → monster stats, boss difficulty, skill damage/mana/cooldown, TTK
- **economy / tokens** → reputation tokens (faucets: 4 élites ×5 + Malachar +200;
  sinks: Gods' Shop `GodsShop.jsx`), gold, GodsShop pricing (BAL01)
- **progression** → XP curve (`xp_curve_mult`), power curve, zone gates, run-scaling
- **loot** → drop rates & rarity (`resourceDrops`, `RARITY_TIERS`, equipment tier drops)
- a file path → load it and infer domain

No arg → ask which.

## Phase 2 — Read the data

- `balance/combat_stats.csv` + `balance/drops_summary.csv` (generated by
  `scripts/generate-balance-csv.mjs` — regenerate first if src changed:
  `node scripts/generate-balance-csv.mjs`).
- Source of truth in `src/data/`: `monsters.js` (baseStats, expReward, goldReward,
  resourceDrops, skillDrop), `skills.js` (damage/mana/cooldown/effects),
  `zones.js` (`ZONE_MULTS`, `scaleMonsterStats`, `getMonsterLevel`, levelRange per
  spot), `equipment.js`, `resources.js`, `recipes.js`, `deities.js`.
- Engine formulas: `src/engine/combat.js` (damage), `src/store/slices/*` (rewards,
  levelups), any `BALANCE` constants (BAL-CSV01).

## Phase 3 — Read intended targets

`docs/DESIGN.md` (validated design specs) and `CONTEXT.md §4` (system state) for
the intended ranges / tuning knobs. `docs/PLAYTESTS.md` for observed results.
These are the baseline for "correct".

## Phase 4 — Analysis (domain-specific)

**Combat:** effective stats per spot via `scaleMonsterStats(base, zone, run)` =
`base × ZONE_MULTS[zone] × 1.0x^run` (note MONLV01 changes run-scaling 1.08→1.03
and adds per-level ×1.25); skill DPS = damage×mult / (cooldown+1) vs mana budget;
time-to-kill of each boss (Crypt Keeper 400hp, Forsaken 900, Malachar 3000) vs
hero power at the gating level; flag any skill strictly dominating another
(same/less mana & cd, ≥ damage).

**Economy / tokens:** faucets vs sinks. Known issue (REP-REBAL01): rank uses the
*spendable* balance `getRankInfo(hero.reputationTokens)` → spending lowers rank;
only ~20 tokens earnable pre-Malachar vs RANK_TIERS Gold 30/Plat 70/Diam 150.
Map every source (quests `reward.reputationTokens`, W01 +200) and sink (GodsShop
prices) and check reachability of each tier.

**Progression:** plot XP need vs XP gained per zone; flag dead zones / spikes;
verify zone unlock conditions (`zones.js unlock.conditions`) align with hero power.

**Loot:** expected kills to obtain each resource/equipment given drop `chance`;
flag anything unobtainable or trivially farmed; check tier drop rates
(EQDROP01b: T1 15/T2 7.5/T3 3/élite 10) are internally consistent.

## Phase 6 — Fix & verify

`AskUserQuestion`:
- `[A] Walk me through the top fix` — guide the edit in the right `src/data` file /
  formula; after, re-run the relevant check. If the value is a design knob,
  remind: update `docs/DESIGN.md` + note in the ticket. If it changed data used by
  balance CSVs, re-run `node scripts/generate-balance-csv.mjs`.
- `[B] Save report to balance/balance-check-[domain]-[date].md`
- `[C] Log findings to docs/PLAYTESTS.md (BAL02/BAL03)`
- `[D] Stop`

Do not commit (Claude ne commite pas — CONTRIBUTING §2). If a data change lands,
remember its structure test + CONTEXT §5 counter (DoD "Contenu data").
